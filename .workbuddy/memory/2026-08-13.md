## 优化：去掉每次起 server，前端 file:// 直接可用
- 用户反馈每次流水线都要起 HTTP server 麻烦，希望"前台读取分析填进 html"。根因：`run.py` 在流水线开头把 pending 占位符烤进 `frontend/usd-liquidity-monitor/data.js`，导致 `app.js` 的 `loadJson` 检测到占位符后去 fetch `/output/latest/analysis.json`，只有 server 下才取得到。
- 新增 `scripts/build_datajs.py`：模型 `publish` 后运行，把已发布（status=published）的 `analysis.json` + `dashboard_data.json` 烤进 `data.js`。`loadJson` 见非 pending 全局变量即零 fetch 直接渲染，`index.html` 可 `file://` 双击打开、无需 server。
- 同步改 `scripts/analysis_validator.py`：`publish` 成功时把 `meta.status="published"` 写入 analysis.json 文件本身（之前只写在外层打印封装），让文件自描述、也满足 build_datajs 的 `--require-published` 守卫。
- 已停掉上轮的后台 8771 server，重烤 data.js（596548 字节，含 published 真分析，node --check 通过）。更新 SKILL.md 与 MEMORY.md 流水线约定：步骤③改为"发布后运行 build_datajs.py"，不再"启动本地预览 server"。
