# 测试 Prompt：让 Agent 从 0-1 构建「美元流动性观测系统」

> 用途：把下面「可直接投喂的 Prompt」整段复制，粘贴给具备联网与文件/命令执行能力的 Agent。
> 设计原则：轻约束、重自主。由 Agent 自行判断需要哪些数据、用什么分析框架、如何设计前端、甚至自行拟定分析用的提示词。流程钉死为「抓取 → 落表去重 → 分析 → 前端展示」。你只需在 Agent 要求时给出密钥，最后打开它产出的看板、查看数据表即可观测。
> 你只需在 Agent 要求时给出 FRED_API_KEY 等密钥，最后打开它产出的 HTML 看板、查看数据表即可观测。

---

## 可直接投喂的 Prompt（复制以下全部内容）

```
请自主从零构建一套美元流动性观测系统：

目标
持续观测美元流动性状况。你拥有充分自主权：由你判断需要哪些数据、用哪些数据源、采用什么分析框架、如何设计前端、以及用什么提示词来做分析。
你必须实现的流程，严格按四步，且可重复运行
1. 抓取数据：调用官方或权威数据源实时拉取真实数据，并回抓一段历史时期。回抓长度以一个月为基础，具体视数据源的可得频率与覆盖范围而定，应足以支撑趋势观察。严禁编造数值或用训练记忆填充。
2. 落表：将抓取结果写入一份人类可观测的数据表。关键约束：每次写入都必须去重，按日期做主键 upsert，重复运行不产生重复行、不丢失已有历史。
3. 分析：用你自行设计的分析框架与提示词，对落表数据做结构化研判，产出分析结论。
4. 前端展示：基于数据表与第 3 步的分析结论，生成一个自包含的 HTML 文件，前端要尽可能美观可读，使用米白色风格：我需要看到结论、重要指标和风险点、指标折线图、指标的讲解，其他功能由你自行设计。

API Key 处理
若某数据源需要 API Key，请主动向我询问，不收费的数据源我会提供；拿到后通过环境变量读取，绝不在代码里硬编码。


---

## 评测者使用说明

1. 投喂：把上面代码块整段复制给被测 Agent。Agent 会自己建目录、写代码、运行；当它询问 API Key 时，你提供 FRED_API_KEY 及它需要的其他密钥。
2. 运行与复跑：Agent 实现后，你可在其产物目录重跑抓取脚本验证去重，重复运行数据表行数不增、历史不丢。
3. 观测：打开 HTML 看板，核对数据表各列与历史跨度。把整个产物目录放入 submissions 下的模型名目录，再跑 score.py 做机判初筛，含去重与回抓跨度检查。
4. 记录：按 EVAL_RULES.md 的模板逐模型逐 run 记录状态与理由。

> 备注：eval/fixtures/2026-07-26/ 保留为本项目参考快照，真实数据加参考研判，可作数据结构对标样例；它不是测试输入，被测 Agent 应拉取它自己运行当时的最新数据并回抓历史。
